# 花候 FlowerCast 项目说明

## 一句话定义

花候是一套把“场地条件、植物习性和四季景观”连接起来的低维护花境推演模型，帮助城市园艺使用者从“凭感觉买花”转向“按约束做设计”。

## 问题与机会

城市微花园具有面积小、环境边界复杂、使用者园艺知识差异大的特点。传统销售通常按品种陈列，消费者容易买到单株健康但组合不合适的植物，最终出现：

1. 光照不适导致长势差；
2. 花期集中在少数月份，其他季节景观空缺；
3. 观赏效果好但养护工作量超出使用者能力；
4. 高矮、花期和色彩缺少节奏，种植后接近“样品拼盘”；
5. 方案依赖设计师个人经验，难以解释和复用。

AI 擅长处理组合与约束，但不能替代现场园艺判断。FlowerCast 的创新点不是让 AI“凭空设计花园”，而是把可表达的园艺规则变成透明模型，让 AI 辅助组合和推演，最终由使用者复核。

## 产品如何工作

### 输入

- 城市及对应耐寒区
- 面积
- 全日照、半日照或荫蔽
- 土壤 pH 与水分状态
- 每周可用于养护的时间
- 材料预算
- 四季均衡、强调季相、低水、传粉友好或常绿结构等目标
- 自然式、结构式或村舍式风格

### 输出

- 6–9 类植物的推荐阵容及建议数量
- 每种植物的适配分与六个维度评分
- 12 个月开花/结构覆盖图
- 后景到前景的示意布局
- 全年养护日历
- 初始材料费、年度养护成本、年灌溉量和生态指数
- 需要复核的风险提示
- CSV 配置单

## 用户与价值

| 用户 | 当前困难 | FlowerCast 的价值 |
| --- | --- | --- |
| 阳台/庭院园艺爱好者 | 选品依赖短视频和图册，忽略场地约束 | 用少量输入得到可解释的候选组合 |
| 社区花园组织者 | 多人维护，时间与认知不一致 | 输出共享养护日历和统一配置单 |
| 小型园艺服务商 | 方案依赖个人经验，沟通成本高 | 快速形成方案底稿并向客户说明依据 |
| 园艺教学场景 | 规则抽象，学生难以建立系统思维 | 参数可调，能观察约束变化对结果的影响 |

## 创新点

### 1. 从“单株推荐”变为“季相组合”

除单项适配分之外，选择过程增加新花期增益和形态多样性规则，避免推荐结果集中在同一月份或同一种植物形态。

### 2. 从“视觉方案”变为“可维护方案”

把使用者每周养护时间纳入评分，并在输出中给出月度工作量和灌溉估算，让设计结果与现实照料能力对齐。

### 3. 从“经验黑箱”变为“可解释模型”

每株植物可展开查看光照、气候、pH、水分、养护和目标六项分数；权重直接展示在网页中。

### 4. 从“网页展示”变为“可交付工具”

支持场景预设、本地保存、CSV 下载和打印 PDF，能够进入实际选品与沟通流程。

## 商业可行性

当前版本适合先作为课程原型和作品集，而不是立即承诺商业收入。可验证的最小路径是：

1. 与 2–3 家本地苗圃核对植物供应和价格；
2. 找 10 位阳台/庭院用户完成场景测试；
3. 在 3 个真实小场地记录 6–12 个月成活、花期和维护工时；
4. 用真实数据校准气候、水分与维护参数；
5. 再探索面向园艺服务商的方案底稿订阅或按次生成服务。

主要成本来自植物数据维护、真实场地验证和专家复核。壁垒不在网页本身，而在持续积累的本地植物参数、失败案例与场地反馈。

## 社会责任与边界

- 默认不推荐已知高入侵风险材料；
- 对湿热、低维护、预算不足和极端匹配场景给出风险提示；
- 不输出“保证成活”或“保证花期”的结论；
- 数据与计算结果不收集到服务器，网页原型完全在本地运行；
- 生产使用前必须进行现场勘察和当地园艺人员复核。
